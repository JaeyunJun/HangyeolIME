# 한결 (HangyeolIME)

한결은 **Manwoo Yi**([@navilera](https://github.com/navilera))님의 [NavilIME for Mac](https://github.com/navilera/NavilIMEforMac)에서 출발한 포크로, 두벌식 전용으로 다시 다듬은 macOS 입력기입니다. 원작의 GPLv3를 따릅니다.

나빌 입력기는 원작자가 세벌식 318Na 자판을 직접 디자인하고, 리눅스/윈도우/맥에서 쓸 수 있도록 입력기를 직접 구현한 프로젝트입니다. 나는 세벌식을 쓰지 못하지만 macOS 기본 한글 입력기의 불안정함이 싫어서, 이 가볍고 깔끔한 입력기를 두벌식 전용으로 커스터마이징해서 쓰고 있습니다.

## 설치

> **지금은 직접 빌드해서 쓰는 분을 위한 저장소입니다.** 내려받아 바로 설치하는 앱은 아직 없습니다.
> 개인 Apple 개발자 계정을 마련하면, Apple 서명·공증을 받은 설치 파일을 릴리스로 제공할 계획입니다.

macOS 13.5 이상, Xcode가 필요합니다(Apple 계정은 필요 없음). 서명은 빌드 스크립트가 이 Mac 전용
자체 서명 인증서를 만들어 처리하므로, 빌드한 앱은 그 Mac에서만 씁니다.

```
git clone https://github.com/JaeyunJun/HangyeolIME.git
cd HangyeolIME
git checkout <버전 태그>    # 예: v2.0.0. 생략하면 개발 중인 main
Tools/build-ime.sh
```
`Tools/build-ime.sh`는 2.0.0-alpha.3부터 있습니다. 그 전 버전은 Xcode에서 직접 빌드해야 합니다.

1. 시스템 설정 → 키보드 → 입력 소스 → **+ → 한국어 → 한결 두벌식**을 추가합니다.
2. (선택) 아래 특수키 조합을 쓰려면 입력기 메뉴의 "특수키 조합" 항목에서 손쉬운 사용 권한을 허용합니다.
   한글 입력에는 필요 없습니다.

버전 목록은 [Releases](https://github.com/JaeyunJun/HangyeolIME/releases)에 있습니다(지금은 소스와 변경 내용만).
pre-release(`-alpha`)는 알려진 문제가 있었거나 아직 검증 중인 버전입니다 — [버전과 릴리스](#버전과-릴리스).

## 기능 (원본 대비)

### 세벌식 제거, 두벌식 전용
- 세벌식 318, 390 키보드 코드 전부 삭제
- 트레이 메뉴에서 키보드 선택 제거
- 두벌식 같은 자음 연속(ㄷㄷㄷ) 합치기 옵션 제거, 항상 분리 입력으로 고정

### 특수키 조합 (선택 기능, 전역 동작)

68배열처럼 `` ` `` 키가 따로 없는 키보드를 쓰는 제작자의 취향으로 넣은 기능입니다.
필요 없으면 권한을 주지 않으면 되고, 한글 입력은 그대로 됩니다.

| 키 조합 | 입력 |
|---------|------|
| Shift + ESC | `~` |
| Cmd + ESC | `` ` `` |
| Cmd + `\` | `₩` |

- **한글/영문 등 입력기 상태와 무관하게** 동작합니다. 조합은 `CGEventTap` 한 경로에서만
  처리합니다 — IMK 입력 경로는 ⌘ 조합을 AppKit의 키 이퀴벌런트 단계에서 뺏겨 아예 받지
  못하므로, 표를 양쪽에 두면 한글 상태에서 `` ` ``와 `₩`가 나오지 않습니다.
- 한글 상태에서는 탭이 이벤트를 삼키고 한결에 직접 넘깁니다. 조합 중인 글자를
  먼저 확정한 뒤 그 뒤에 기호를 붙입니다(`한` 조합 중 `Shift+ESC` → `한~`).
  문자를 바꿔 넣은 이벤트를 흘려보내면 입력기의 `handle`까지 오지 않아 아무것도
  입력되지 않기 때문입니다. 영문 등 다른 입력 소스에서는 문자를 바꿔 앱으로 흘려보냅니다.
- 모디파이어는 **정확히 일치**해야 합니다. (`Cmd+Shift+ESC`는 어느 조합에도 걸리지 않음)
- 조합을 가로채려면 모든 키 입력을 볼 수 있어야 해서 **손쉬운 사용(Accessibility) 권한**이
  필요합니다. 한결은 세 조합 말고는 키를 건드리지 않고 아무것도 기록하거나 내보내지 않습니다.
  권한이 없으면 세 조합만 동작하지 않습니다.
- 입력기 메뉴의 "특수키 조합: …" 항목이 실제 상태(꺼짐 / 탭 꺼짐 ⚠️ / 켜짐 ✓)를 보여주고,
  누르면 설명 창이 열립니다. ‘권한 허용하기’ 하나로 macOS 권한 요청 창을 띄우고(설명 창에
  가리지 않음), 떠 있는 동안 1초마다 다시 조회해 권한이 잡히면 3초 뒤 스스로 닫힙니다.
  시스템 설정 목록의 표시가 아니라 프로세스가 실제로 받은 권한을 보여주므로, 목록엔
  켜져 있는데 꺼짐이면 서명이 바뀐 것입니다 — 목록에서 지우고(−) 다시 추가하세요.
- 전역 키 가로채기는 App Sandbox에서 동작하지 않으므로 이 포크는 샌드박스를 끕니다.
  (App Store가 아닌 `~/Library/Input Methods` 직접 설치 방식이라 문제 없음)

### 암호 프롬프트에서 입력기 자동 비켜서기

한글 상태로 비밀번호를 치면 한글이 들어가 매번 수동으로 영문 전환해야 하던 문제를 없앴습니다.

- macOS가 secure input을 켜는 자리(잠금 화면, 키체인, 앱의 암호 필드)에서는 한결이
  **스스로 조합을 멈추고 키를 그대로 흘려보냅니다.** 한/영 상태는 건드리지 않으므로
  프롬프트를 빠져나오면 원래 한글 상태 그대로입니다.
- macOS는 secure input을 켤 뿐 **입력 소스를 영문으로 갈아주지는 않습니다.** (측정으로 확인)
  그래서 입력기가 직접 비켜서야 합니다.

**터미널의 `sudo`·`ssh`·`git` 프롬프트도 자동으로 처리합니다.** 터미널 앱은 pty 상태를
보지 않아 secure input을 켜주지 않으므로, 입력기가 직접 tty를 봅니다:

| 프로그램 | 터미널 모드 | 에코 | 판정 |
|---|---|---|---|
| `cat` (평범한 입력) | 정규 | on | — |
| `getpass`·`sudo`·`ssh` | **정규** | **OFF** | **암호 프롬프트** |
| `vi`·`top` (TUI) | raw | OFF | 오탐 아님 |

비밀번호를 읽는 프로그램은 tty를 **정규 모드 + 에코 끔**으로 만들고, 전체화면 TUI는
raw 모드라 구분됩니다. 그래서 `sudo`뿐 아니라 `ssh`, `git` 자격증명, `passwd`, `su`,
python `getpass` 등 **에코를 끄고 비밀번호를 읽는 모든 것**이 커버됩니다.
감지하면 `EnableSecureEventInput()`을 켜므로 그동안 다른 앱의 이벤트 탭도 차단됩니다.

**지금 입력 중인 곳만 봅니다.** 맨 앞 앱 소유의 tty(프로세스 부모를 따라가 그 앱에 닿는 것,
맨 앞 앱이 터미널이면 tmux처럼 어느 앱에도 속하지 않는 것 포함) 중에서, 가장 최근에 키 입력을 받은 tty와 그보다
2초 이내에 입력을 받은 tty만 봅니다. 뒤쪽 탭에 떠 있는 암호 프롬프트나 에코를 끈 채 남은
tty 때문에 다른 앱의 한글까지 막히지 않습니다.

입력기가 일부러 조합을 멈춘 동안(터미널 암호 감지, 다른 앱이 켜 둔 secure input)에는
입력기 메뉴 맨 위에 그 이유가 표시됩니다. 메뉴 막대는 한글인데 영문이 나오면 메뉴를 열어 보세요.

셸 설정은 필요 없습니다. 앱을 빌드해서 설치하면 그대로 동작합니다.

동작이 깨졌는지 확인할 때는 `swift Tools/secure-test.swift`를 쓰면 됩니다. secure
input을 켠 채로 에코는 남겨두고 한 줄을 받으므로, 비밀번호 없이 "입력기가 비켜서는가"를
눈으로 확인할 수 있습니다. 한글 상태로 `abcd`를 쳐서 `[abcd]`가 나오면 정상입니다.

> 참고: secure input은 프로세스 전역 참조 카운트입니다. 어떤 앱이 켜놓고 끄지 않으면
> 한글이 어디서도 조합되지 않고 특수키 조합도 멈춥니다. 그 증상이면 화면을
> 잠갔다 풀면 해소됩니다.

### 한/영 전환은 macOS 입력 소스로 일원화

입력기 내부의 한/영 모드(`self_eng_mode`)와 전용 단축키(오른쪽 Command 등)를 제거했습니다.
한/영은 **macOS 입력 소스 선택**으로만 바뀝니다 — 한글은 한결, 영문은 ABC입니다.
⌃Space(기본) 또는 본인이 지정한 단축키를 쓰세요.

내부 모드는 macOS가 알 수 없는 상태였습니다. 어느 앱에서든 "한결 선택됨"으로만
보이니 OS가 앱별 기억도, 암호 필드 대응도 해줄 수 없었습니다. 입력 소스로 일원화하면
OS가 상태를 알게 됩니다.

> Caps Lock으로 전환한다면 macOS의 탭/홀드 판별 때문에 지연이 붙습니다.
> `hidutil`로 Caps Lock을 F19로 돌리고 "입력 메뉴에서 다음 소스 선택"에 바인딩하면
> 없앨 수 있습니다. ⌃Space 같은 조합키는 해당 없습니다.

### 입력 소스가 바뀐 직후의 키

Raycast처럼 열리면서 입력 소스를 ABC로 바꾸는 앱에 바로 타이핑해도 첫 글자가 한글로
들어가지 않습니다. 전환을 요청한 뒤 앱에 실제로 반영되기까지 100~200ms(실측)가 걸리고
그 사이 키는 여전히 입력기로 오는데, 입력기가 키마다 "시스템 입력 소스가 아직 한결인가"를
확인해 이미 바뀌었으면 조합하지 않고 흘려보냅니다. 누가 전환했든(앱 자체 설정, macOS의
"문서의 입력 소스로 자동 전환", 단축키) 같습니다. 확인 비용은 키당 수십 µs 이하입니다
(입력기 안 실측 20~40µs, 별도 프로세스 실측 0.2µs).

앱마다 언어를 따로 쓰고 싶으면 macOS의 "문서의 입력 소스로 자동 전환"(시스템 설정 →
키보드 → 입력 소스)을 쓰세요. 입력기 자체의 앱별 한/영 고정 기능은 없앴습니다.

### UI 단순화
- 옵션 창 완전 제거. 입력기 메뉴에는 특수키 권한 상태 항목 하나만 있습니다.

### 보안

- Release 빌드는 `get-task-allow` 엔타이틀먼트를 갖지 않습니다. Xcode가 개발 인증서
  서명 시 자동 주입하는 것인데, 이게 있으면 Hardened Runtime이 켜져 있어도 다른
  프로세스가 디버거를 붙일 수 있습니다. 입력기는 모든 키 입력을 지나보내므로
  `Signing.xcconfig`에서 Release에 한해 주입을 끕니다.
- 입력 내용은 어디에도 기록되지 않습니다. 로그는 Release에서 컴파일 단계에서 제거되고,
  네트워크 코드도 입력을 파일로 쓰는 경로도 없습니다.

버전별 변경 내용은 [CHANGELOG.md](CHANGELOG.md)에 있습니다.

## 버전과 릴리스

[유의적 버전](https://semver.org/lang/ko/) `주.부.수`를 씁니다. 원작자 버전(마지막 7.0)과는 별개인 이 포크만의 번호로, 1부터 셉니다. 포크는 원작자 7.0을 바탕으로 합니다.

- **주**: 쓰던 방식이 바뀌는 변경(기능 제거, 입력 소스를 다시 추가해야 함 등). 1 = 세벌식 제거, 2 = 내부 한/영 모드 제거·입력 모드 구조
- **부**: 기능 추가. **수**: 버그 수정만.

릴리스는 작업한 날짜 단위로 냅니다.

1. 새 버전은 먼저 **pre-release** `X.Y.Z-alpha.N`으로 냅니다. 같은 목표 버전에서 다시 고치면 `alpha.N+1`.
2. 써 보고 문제가 없으면 **같은 커밋**에 정식 `X.Y.Z`를 붙입니다. 정식은 "문제없이 쓴 것"만 받습니다.
3. 문제가 있던 alpha는 그대로 남기고, 릴리스 노트 맨 위에 **알려진 문제**와 고친 버전을 적습니다.
4. 정식 버전에서 나중에 문제가 발견되면 태그는 그대로 두고 노트에 알려진 문제를 덧붙인 뒤
   다음 수 버전으로 고칩니다.

릴리스 노트의 원본은 [CHANGELOG.md](CHANGELOG.md) 한 파일입니다. 버전마다 `## [버전]` 절이 있고,
그 절이 그대로 GitHub 릴리스 노트가 됩니다. 저장소만 받아도 전체 이력을 볼 수 있고 릴리스 페이지와
내용이 어긋나지 않습니다. 작업 중인 내용은 `## [Unreleased]`에 쌓았다가 릴리스할 때 버전 절로 옮깁니다.

```
Tools/release.sh 2.1.0-alpha.1            # 지금 커밋으로 pre-release
Tools/release.sh 2.1.0 <alpha의 커밋>     # 써 보고 문제없으면 같은 커밋을 정식으로 (CHANGELOG에 2.1.0 절 먼저)
```
앱 버전(`MARKETING_VERSION`)은 alpha를 뗀 목표 버전이고, 스크립트가 커밋의 값과 맞는지 확인합니다.

## 개발

### 빌드·설치
```
Tools/build-ime.sh          # Release 빌드 → ~/Library/Input Methods 설치 → 실행 확인
Tools/build-ime.sh Debug    # 진단용. os_log에 입력 내용이 남으니 평소엔 쓰지 말 것
```
설치 뒤 새 빌드가 실제로 뜨는지 확인하고, 안 뜨면 직전 설치본으로 되돌립니다
(입력기가 죽으면 그 입력 소스로는 아무것도 칠 수 없으므로).

처음 한 번은 시스템 설정 → 키보드 → 입력 소스 → + → 한국어에서 한결 두벌식을 추가하세요.
특수키 조합을 쓰려면 입력기 메뉴의 "특수키 조합" 항목에서 손쉬운 사용 권한을 허용합니다(선택).

### 코드 구조
- `HangyeolInputController`: 입력기 본체. 키 → 한글 엔진 → 조합 중/확정 글자 반영
- `Hangul/`: 한글 엔진(`Hangul`), 자모(`Jamo`), 두벌식 배치·조합 규칙(`Dubeolsik`)
- `KeyMap`(키 위치표), `ComposeBypass`(조합 건너뛰기 패턴), `InputSource`(입력 소스 조회),
  `InputSession`(지금 입력 중인 세션, 끊긴 세션 복구)
- `SpecialKeyTap`(특수키 전역 탭), `TTYPasswordWatcher`(터미널 암호 감지),
  `InputMenu`(입력기 메뉴), `PermissionWindow`(특수키 권한 창), `Log`(Debug 전용 로그)

### 입력 모드 구조
Apple 입력기처럼 입력기(`com.jaeyunjun.inputmethod.HangyeolIME`) 아래 입력 모드 하나
(`...HangyeolIME.Dubeolsik`, 언어 ko)를 두고, 사용자는 이 모드를 선택합니다(`Info.plist`의
`ComponentInputModeDict`). 그래서 현재 입력 소스 ID는 모드 ID이고, 코드는 번들 ID로
한결인지 판단합니다(`InputSource`). 목록에 보이는 이름은 `*.lproj/InfoPlist.strings`.

### 입력기 아이콘
메뉴 막대·입력 위치 표시에는 입력 모드의 `TISIconLabels`(Primary = "가")를 macOS가 직접
그립니다(앱 수준에 두면 무시됩니다). Apple 한국어 입력기가 쓰는 방식입니다. 그림 아이콘(`hangyeol.tiff`, 투명 배경의 '가'
템플릿 이미지, `TISIconIsTemplate`)은 그 밖의 자리용이며 `swift Tools/make-icon.swift
HangyeolIME/hangyeol.tiff`로 다시 만듭니다. 바꾼 뒤에는 macOS 아이콘 캐시 때문에 입력 소스를
바꿨다 오거나 다시 로그인해야 보일 수 있습니다.

### 한글 엔진 테스트
```
Tools/hangul-test.sh    # 고정 문장 + 무작위 20만 타의 엔진 출력이 기준과 같은지 확인
```
`HangyeolIME/Hangul/`을 고친 뒤 돌립니다. 기준 해시는 정리 전 원작자 엔진의 출력입니다.

### 코드 서명 원칙: 로컬 인증서
손쉬운 사용 권한은 앱의 코드 서명 신원에 묶입니다. ad-hoc 서명은 바이너리 해시가
신원이라 재빌드할 때마다 권한이 날아갑니다. 그래서 이 저장소는 **로그인 키체인의
자체 서명 인증서 `HangyeolIME Local Signing`으로 서명하는 것이 기본값**입니다
(`HangyeolIME/Signing.xcconfig`). 신원이 "번들 ID + 인증서"로 고정되어 재빌드해도
권한이 유지됩니다.

- 인증서는 키체인에 있으므로 저장소를 지웠다 다시 받아도 그대로 쓰입니다.
- 없으면 `Tools/setup-signing.sh`가 만듭니다(`build-ime.sh`가 자동으로 부름, 이미 있으면 건너뜀).
  개인 키는 `codesign`만 쓸 수 있게 제한됩니다.
- Apple 계정·Xcode 로그인은 필요 없습니다.
- 인증서를 새로 만들면(다른 Mac, 키체인 초기화 등) 권한을 한 번 다시 허용해야 합니다.
- 이 인증서에는 Team ID가 없어서, Debug 빌드가 코드를 `.debug.dylib`로 분리하면
  Hardened Runtime 라이브러리 검증에 걸려 실행 즉시 죽습니다. 그래서
  `ENABLE_DEBUG_DYLIB = NO`를 기본값에 넣었습니다.
- 다른 신원(Apple Development 등)을 쓰려면 `HangyeolIME/Local.xcconfig`로 덮어쓰세요
  (`Local.xcconfig.example` 참고, `.gitignore` 대상).
